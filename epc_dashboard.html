01 — Contextบริบท

Context & Objective บริบทและวัตถุประสงค์

The Challengeความท้าทาย

Enterprise ERPs like Epicor combine a deeply fragmented relational database with rigid standard reports. Operational teams had no reliable real-time verification tools, and executives lacked timely visibility into Gross Profit (GP), cost structure, and operating cash flow.

ระบบ ERP ขนาดใหญ่อย่าง Epicor มีโครงสร้างฐานข้อมูลกระจายหลายตาราง และรายงานมาตรฐานไม่ตอบโจทย์ธุรกิจจริง ทีมปฏิบัติการจึงขาดเครื่องมือตรวจสอบข้อมูลแบบ Real-time และผู้บริหารมองไม่เห็นภาพรวมทางการเงิน (กำไรขั้นต้น โครงสร้างต้นทุน และกระแสเงินสด) ได้ทันท่วงที

The Solution: Dual-Layer Architectureโซลูชัน: สถาปัตยกรรม 2 ชั้น

Layer 1 · Operationalชั้นที่ 1 · ปฏิบัติการ

~30 Native Epicor Dashboards

Cross-departmental requirements gathered, formal System Specifications authored, and nearly 30 BAQ dashboards built for daily operational auditing.

เก็บ Requirement จากผู้ใช้จริง ออกแบบ System Specification และสร้างแดชบอร์ดใน Epicor เกือบ 30 ชิ้นงาน ให้พนักงานตรวจสอบข้อมูลหน้างานได้ทันที

Layer 2 · Executiveชั้นที่ 2 · ผู้บริหาร

Executive Financial BI Pipeline

Cross-module BAQs exposed via REST API (JSON) feed interactive Power BI dashboards that track GP, cost structure, and cash flow.

พัฒนา BAQ เชื่อมข้อมูลรายได้ ต้นทุน และกระแสเงินสด เปิดเป็น REST API (JSON) ดึงเข้า Power BI สร้าง Executive Financial Dashboard

02 — Operational Layerชั้นปฏิบัติการ

Operational Reports & System Mapping รายงานปฏิบัติการและ System Mapping

A Single Source of Truth inside the ERP: nearly 30 custom inquiry dashboards across 4 functional pillars.

สร้าง Single Source of Truth ภายใน ERP ด้วยแดชบอร์ดเกือบ 30 โมดูล ครอบคลุม 4 สายงานหลัก

ICRID008ICRID003

Last-Mile COD Reconciliation & Dynamic Aging

COD tracking links OrderHed, ShipHead.DoStatus_c = 'Delivered', InvcHead, and CashDtl. It is paired with a 7-tier micro-aging dashboard driven by a user-input Criteria Date.

ติดตามเงิน COD เชื่อม OrderHed, ShipHead.DoStatus_c = 'Delivered', InvcHead และ CashDtl พร้อมแดชบอร์ดอายุหนี้ 7 ช่วงที่คำนวณจาก วันที่ Criteria ที่ผู้ใช้กรอก

ICRID001

AR Invoice Verification & Accounting Export

Conditional logic for Net Price, Advance Bill Credits, and VAT separation, plus automated TRCloudAcc mapping for external accounting firms on TRCloud.

ลอจิกคำนวณยอดขายสุทธิ ยอดรับล่วงหน้า แยกภาษี และ Mapping รหัสบัญชี TRCloudAcc ตาม Format ที่สำนักงานบัญชีใช้นำเข้า TRCloud

ICRID002

Procure-to-Pay & Cost Tracking

End-to-end flow from POHeader/PODetail and UnitCost / ExtCost through RcvDtl and AdvancePayBal to APInvHed.

เชื่อมข้อมูลจัดซื้อและต้นทุนตั้งแต่ POHeader/PODetail ต้นทุนต่อหน่วย การรับของ (RcvDtl) เงินจ่ายล่วงหน้า จนถึงตั้งหนี้ (APInvHed)

ICRID004ICRID005ICRID007

Warehouse & Inventory Movement Control

Raw PartTran logs turned into auditable stockcards, reason-coded misc. issue trackers, and split In/Out bin transfers.

แปลง PartTran เป็นสต็อกการ์ด รายงานเบิกจ่ายเบ็ดเตล็ดตาม Reason Code และรายงานโอนย้าย Bin แยกขาออก/ขาเข้า

Interactive Spec Explorer: 7 Flagship Modules Spec Explorer: 7 โมดูลเด่น Select a Spec ID to view its spec, simulated ERP UI, and BAQ logic เลือกรหัส Spec เพื่อดูตาราง Spec หน้าจอจำลอง ERP และคำสั่ง BAQ

Recreated from real dashboards using sanitized data to protect company confidentiality. จำลองจากหน้าจอจริงโดยใช้ข้อมูล Sanitized เพื่อปกป้องความลับของบริษัท

03 — Executive Layerชั้นผู้บริหาร

API Pipeline & Executive Financial BI API Pipeline และ Executive Financial BI

Operations rely on line-item ERP grids, while leadership needs the big picture. An automated REST API pipeline feeds Power BI with GP, cost structure, and operating cash flow.

ทีมปฏิบัติการใช้แดชบอร์ด ERP ตรวจรายการรายวัน แต่ผู้บริหารต้องการภาพรวม จึงสร้าง Pipeline ผ่าน REST API เข้าสู่ Power BI เพื่อวิเคราะห์ GP ต้นทุน และกระแสเงินสด

BAQ → REST API (JSON) Consolidation

Cross-module BAQs consolidate net revenue (InvcHead / InvcDtl), procurement and inventory costs (PODetail / PartTran), and cash in/out (CashDtl / APInvHed) into one JSON endpoint.

เขียน BAQ รวมข้อมูลข้ามโมดูล ทั้งรายได้สุทธิ (InvcHead / InvcDtl) ต้นทุนและการเบิกจ่าย (PODetail / PartTran) และเงินสดรับ-จ่าย (CashDtl / APInvHed) เปิดเป็น Endpoint แบบ JSON

Financial Modeling in Power BI (DAX)

The data model and DAX measures were built independently for GP & GP Margin %, COGS & Logistics Cost %, and Net Operating Cash Flow & Working Capital.

สร้าง Data Model และสูตร DAX คำนวณ GP และ GP Margin %, สัดส่วน COGS และค่าขนส่ง และ กระแสเงินสดสุทธิและเงินทุนหมุนเวียน

  1. 1 Epicor Tables InvcHead · PODetail · PartTran · CashDtl · APInvHed
  2. 2 BAQ Cross-module consolidationรวมข้อมูลข้ามโมดูล
  3. 3 REST API (JSON) Exposed endpointเปิดเป็น Endpoint
  4. 4 Power BI + DAX Executive dashboardแดชบอร์ดผู้บริหาร

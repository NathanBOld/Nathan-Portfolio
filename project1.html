Automated AR Reconciliation & Multi-Invoice Payment Splitting

A zero-formula automation built with Power Query and Excel VBA to map, audit, and reconcile Cash on Delivery (COD) payment data across 3PL carriers, TMS, and ERP systems. ระบบกระทบยอดลูกหนี้ (3-Way Reconciliation) และแยกไฟล์ตัดรับชำระเงินอัตโนมัติแบบไม่ต้องพึ่งสูตร Excel พัฒนาด้วย Power Query ETL และคำสั่ง VBA Macro เชื่อมข้อมูลระหว่าง ขนส่ง (3PL), ระบบ TMS และ ERP

1. Project Overview: 2 Perspectives 1. ภาพรวมโปรเจกต์จาก 2 มุมมองหลัก

1. Business Perspective 1. มุมมองด้านธุรกิจ (Business Perspective)

Goal: Optimize operational time and eliminate financial leakage.

  • Reduced manual file generation (Copy/Paste) time from >2 hours to mere minutes.
  • Eliminated human errors and visual clutter caused by fragile manual VLOOKUP formulas.
  • Prevented duplicate document uploads into the TMS system proactively.
  • Seamless Downstream Integration (Tab: PostToRV): Automatically outputs a structured 3-column table—PaidDate/Customer (composite batch key: ddMMyyyy + 3PL Code + 3PL Payment Run#, e.g., 07112025DHL6, used to separate distinct lump-sum payment batches), InvoiceNumber, and Amount—pre-filtered using TRCloud's Status = Debtor to exclude already-posted RV invoices, ready for direct Copy & Paste into the Bulk RV API Web App.

เป้าหมาย: ลดเวลาปฏิบัติงานหน้างานและป้องกันความผิดพลาดทางการเงิน

  • ลดเวลาการทำไฟล์ตัดรับชำระ (Copy/Paste) จากเดิม มากกว่า 2 ชั่วโมงต่อวัน เหลือเพียงไม่กี่นาที
  • ขจัดความผิดพลาดจากคน (Human Error) และปัญหาไฟล์ค้างจากการผูกสูตร VLOOKUP จำนวนมาก
  • ป้องกันการอัปโหลดเอกสารตัดรับชำระซ้ำเข้าสู่ระบบ TMS ล่วงหน้าอย่างเป็นระบบ
  • เชื่อมต่อกระบวนการตัดหนี้ ERP แบบไร้รอยต่อ (Tab: PostToRV): สร้างตารางข้อมูลสำเร็จรูป 3 คอลัมน์ ได้แก่ PaidDate/Customer (รหัสแยกก้อนชำระเงิน: วันที่รับชำระ ddMMyyyy + รหัส 3PL + เลข Run ก้อนการจ่ายเงินของ 3PL เช่น 07112025DHL6), InvoiceNumber และ Amount โดยกรองเอาเฉพาะบิลที่ยังไม่เคยตัดรับชำระด้วย Status = Debtor จากระบบ TRCloud (TRC) เพื่อให้พนักงาน Copy & Paste ส่งต่อเข้าสู่ Bulk RV API Web App ได้ทันทีโดยไม่เกิดการโพสต์ RV ซ้ำ

2. Technical Perspective 2. มุมมองด้านเทคนิค (Technical Perspective)

Goal: Build a robust, scalable, and foolproof data pipeline.

  • Power Query (ETL & Gatekeeper): Reconciles data across 3rd-Party Logistics, TMS, and TRCloud ERP. Filters strictly for matched, un-uploaded records and dynamically pre-generates target filenames.
  • Dual-Output & Dual-Gatekeeper Architecture: Prevents duplicate TMS uploads via DO Reconciled and prevents duplicate ERP RV postings in Tab: PostToRV by filtering TRCloud data strictly for Status = Debtor—generating a composite batch key in PaidDate/Customer (ddMMyyyy & 3PL Code & 3PL Payment Run#) alongside InvoiceNumber and Amount to group invoices by exact payment transfer batch.
  • VBA Automation & Zero-Formula Approach: Reads pre-generated filenames to group invoices, auto-creates individual sheets, and exports separate standardized files without fragile cell formulas.

เป้าหมาย: สร้างโครงสร้างประมวลผลข้อมูลที่แข็งแกร่ง รองรับปริมาณข้อมูลสูง และตรวจสอบได้

  • Power Query (ETL & Gatekeeper): กระทบยอดข้อมูล 3 ทาง (3PL, TMS, TRCloud ERP) คัดกรองเฉพาะรายการที่ตรงกันและยังไม่เคยอัปโหลด พร้อมสร้างรหัสชื่อไฟล์ปลายทางให้อัตโนมัติ
  • Dual-Output & Dual-Gatekeeper Architecture: ป้องกันข้อมูลซ้ำทั้ง 2 ระบบ โดยฝั่ง TMS กรองด้วยชีท DO Reconciled ส่วนฝั่ง ERP ในแท็บ PostToRV กรองอินวอยซ์ที่เคย Post RV ไปแล้วออกด้วยฟิลด์ Status = Debtor จากชีท TRC และผูกสูตรสร้างคีย์ PaidDate/Customer (วันที่รับชำระ ddMMyyyy & 3PL Code & Run Number ของก้อนเงินโอน 3PL) คู่กับ InvoiceNumber และ Amount เพื่อใช้แยกก้อนการรับชำระเงิน (RV Batch) อย่างแม่นยำ
  • VBA Automation & Zero-Formula Approach: อ่านรหัสชื่อไฟล์เพื่อแยกสร้างชีทย่อยและส่งออกไฟล์ Excel แยกตามรอบการโอนโดยไม่ต้องพึ่งสูตรในเซลล์

3. Step-by-Step User Guide 3. คู่มือการใช้งานระบบทีละขั้นตอน (Step-by-Step User Guide)

Operational workflow guide for end-users executing daily 3-Way COD Reconciliation (Click any image to enlarge). คู่มือการปฏิบัติงานสำหรับผู้ใช้งานหน้างาน (End-User) ในการทำ 3-Way Reconciliation รายวัน (คลิกที่รูปเพื่อขยายขนาดใหญ่)

1

1. Export & Paste Raw Data

Download raw data reports from 3rd-Party Logistics, TMS, and ERP systems and paste them into the designated color-coded sheets (Green, Orange, Red tabs).

ดาวน์โหลดไฟล์ข้อมูลดิบจากระบบ 3rd-Party Logistics, TMS และ ERP นำมาวางตามชีทที่กำหนด (แท็บสีเขียว, ส้ม, แดง)

2

2. Refresh Power Query Reconciliation

Navigate to the "TMS Check" sheet, enter the target DO Creation Date range, and click the blue Refresh button to automatically execute 3-source reconciliation.

ไปที่ชีท TMS Check ใส่วันที่ของ DO Create Date ที่ต้องการกระทบยอด จากนั้นกดปุ่มสีฟ้า ระบบจะดึงข้อมูลจาก 3 แหล่งมา Reconcile ให้อัตโนมัติ

3

3. Refresh Output Tabs (Create DO & PostToRV)

Click "Refresh" to update both Tab: Create DO (filtered against DO Reconciled) and Tab: PostToRV—which filters TRC for Status = Debtor and constructs PaidDate/Customer (ddMMyyyy + 3PL Code + 3PL Payment Run#, e.g., 07112025DHL6 to separate payment batches), InvoiceNumber, and Amount.

กดปุ่ม "Refresh" เพื่ออัปเดตชีท Create DO และชีท PostToRV ซึ่งกรองเฉพาะบิลที่สถานะใน TRC เป็น Debtor พร้อมสร้างรหัส PaidDate/Customer (วันที่รับชำระ ddMMyyyy + 3PL Code + เลข Run ก้อนชำระเงิน เช่น 07112025DHL6 เพื่อใช้แยกก้อนเงินโอน), InvoiceNumber และ Amount

4

4. Split into Batch Sheets

Click the "Split" macro button to partition the reconciled records into separate worksheets by carrier and payout date.

กดปุ่ม "Split" เพื่อให้ระบบแยกข้อมูลตามกลุ่มชื่อไฟล์ที่สร้างไว้

5

5. Review Generated Sheets

The macro automatically groups invoices into individual sheets and displays a completion confirmation dialog. Click "OK".

ระบบแยกกลุ่มของ Invoice ไปอยู่ในแต่ละชีทอัตโนมัติ และจะมีกล่องข้อความแจ้งเสร็จสิ้นการทำงาน กด "OK"

6

6. Export Individual Files

Click the "Export" button to convert each separated worksheet into an individual upload-ready Excel workbook.

กดปุ่ม "Export" เพื่อส่งออกแต่ละชีทเป็นไฟล์ Excel แยกตามรอบการโอน

7

7. Select Target Folder

Specify the destination folder to save the exported reconciliation files (select an existing directory or create a new folder).

ระบุโฟลเดอร์ปลายทางที่ต้องการเก็บไฟล์ข้อมูล สามารถเลือกโฟลเดอร์ที่มีอยู่แล้ว หรือสร้างโฟลเดอร์ใหม่ก็ได้

8

8. Clear Workspace

Click the "Clear" button to remove temporary split sheets and reset the workbook for the next reconciliation cycle.

กดปุ่ม "Clear" ระบบจะล้างชีทย่อยที่ถูกสร้างชั่วคราวออกทั้งหมด เพื่อเตรียมพร้อมทำงานในรอบต่อไป

9

9. Verify Exported Files

Inspect the generated batch files in the target folder—each named automatically with the payment date and 3PL carrier code.

ตรวจสอบไฟล์ที่สร้างใหม่ในโฟลเดอร์ที่เลือก ซึ่งตั้งชื่อตามวันที่รับชำระและรหัสขนส่งโดยอัตโนมัติ

10

10. Batch Import into TMS

In TMS, navigate to Accounting >> Batch List >> Import. Attach the generated file and select the Last-Mile carrier and payment date indicated by the filename.

อัปโหลดไฟล์บนระบบ TMS โดยไปที่เมนู Accounting >> Batch List >> Import เลือกไฟล์ที่สร้าง แล้วเลือกขนส่ง (Lastmile) และวันที่โอนเงินตามที่ระบุในชื่อไฟล์

11

11. Invoice Data for Bulk RV API System

Go to PostToRV Tab, then copy the data from the InvoiceNumber and Amount columns, open the Bulk RV API Web App. and paste it into the table. Then, use the data from the PaidDate/Customer column to select the customer and specify the document date.

ไปที่ PostToRV Tab แล้วคัดลอกข้อมูลในคอลัมน์ InvoiceNumber และ Amount เปิดลิงค์ Bulk RV API Web App. แล้ววางข้อมูลลงในตาราง และใช้ข้อมูลจากคอลัมน์ PaidDate/Customer เพื่อเลือกลูกค้า และระบุวันที่ของเอกสาร

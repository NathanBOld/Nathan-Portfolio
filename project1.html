Automated AR Reconciliation & Multi-Invoice Payment Splitting

A zero-formula automation built with Power Query and Excel VBA to map, audit, and reconcile Cash on Delivery (COD) payment data across 3PL carriers, TMS, and TRCloud ERP.

ระบบกระทบยอดลูกหนี้ (3-Way Reconciliation) และแยกไฟล์ตัดรับชำระอัตโนมัติแบบไม่ต้องพึ่งสูตร Excel พัฒนาด้วย Power Query ETL และ VBA Macro เชื่อมข้อมูลระหว่างขนส่ง (3PL), ระบบ TMS และ TRCloud ERP

01 — Overviewภาพรวม

Project Overview: 2 Perspectives ภาพรวมโปรเจกต์จาก 2 มุมมอง

Perspective 1มุมมองที่ 1

Businessด้านธุรกิจ

Goal:เป้าหมาย: Optimize operational time and eliminate financial leakage. ลดเวลาปฏิบัติงานและป้องกันความผิดพลาดทางการเงิน

  • Reduced manual Copy/Paste file generation from over 2 hours to minutes per day.
  • Eliminated human errors and file lag caused by fragile VLOOKUP formulas.
  • Proactively prevented duplicate document uploads into TMS.
  • Seamless downstream integration (Tab: PostToRV): outputs a ready-to-paste table of unposted invoices for the Bulk RV API Web App.
  • ลดเวลาการทำไฟล์ตัดรับชำระจาก มากกว่า 2 ชั่วโมงต่อวัน เหลือไม่กี่นาที
  • ขจัด Human Error และปัญหาไฟล์ค้างจากการผูกสูตร VLOOKUP จำนวนมาก
  • ป้องกันการอัปโหลดเอกสารซ้ำเข้าระบบ TMS ล่วงหน้าอย่างเป็นระบบ
  • เชื่อมต่อการตัดหนี้ ERP แบบไร้รอยต่อ (Tab: PostToRV): สร้างตารางบิลที่ยังไม่ตัดรับชำระ พร้อม Copy & Paste เข้าสู่ Bulk RV API Web App ทันที
Perspective 2มุมมองที่ 2

Technicalด้านเทคนิค

Goal:เป้าหมาย: Build a robust, scalable, and foolproof data pipeline. สร้าง Data Pipeline ที่แข็งแกร่ง รองรับปริมาณสูง และตรวจสอบได้

  • Power Query (ETL & Gatekeeper): reconciles 3PL, TMS, and TRCloud data, keeps only matched and un-uploaded records, and pre-generates target filenames.
  • Dual-Gatekeeper Architecture: blocks duplicate TMS uploads via DO Reconciled, and blocks duplicate RV postings by filtering TRC for Status = Debtor.
  • VBA & Zero-Formula Approach: reads the pre-generated filenames, auto-creates batch sheets, and exports standardized files without cell formulas.
  • Power Query (ETL & Gatekeeper): กระทบยอด 3 ทาง (3PL, TMS, TRCloud) คัดเฉพาะรายการที่ตรงกันและยังไม่เคยอัปโหลด พร้อมสร้างชื่อไฟล์ปลายทางอัตโนมัติ
  • Dual-Gatekeeper Architecture: ฝั่ง TMS กรองซ้ำด้วยชีท DO Reconciled ฝั่ง ERP กรองบิลที่เคย Post RV แล้วออกด้วย Status = Debtor จากชีท TRC
  • VBA & Zero-Formula Approach: อ่านชื่อไฟล์เพื่อแยกชีทและส่งออกไฟล์ Excel ตามรอบการโอน โดยไม่พึ่งสูตรในเซลล์

วันที่รับชำระ ddMMyyyy + รหัส 3PL + เลข Run ก้อนโอนของ 3PL ใช้แยกเงินโอนแต่ละก้อนเป็น RV Batch ของตัวเอง และส่งออกในแท็บ PostToRV คู่กับ InvoiceNumber และ Amount

System Architecture & Data Flow สถาปัตยกรรมระบบและผังการไหลของข้อมูล

End-to-end pipeline: 3-source ETL, duplicate prevention, and 3 output tabs — TMS Check (audit), Create DO (split & export to TMS), and PostToRV (paste into the Bulk RV API Web App).

กระบวนการ End-to-End ตั้งแต่ ETL จาก 3 แหล่ง การป้องกันข้อมูลซ้ำ จนถึงผลลัพธ์ 3 แท็บ ได้แก่ TMS Check (ตรวจสอบ), Create DO (แยกไฟล์อัปโหลดเข้า TMS) และ PostToRV (วางข้อมูลเข้า Bulk RV API Web App)

03 — User Guideคู่มือการใช้งาน

Step-by-Step User Guide คู่มือการใช้งานทีละขั้นตอน

Daily operational workflow for end-users. Click any image to enlarge. ขั้นตอนการปฏิบัติงานรายวันสำหรับผู้ใช้งานหน้างาน คลิกที่รูปเพื่อขยาย

1

Export & Paste Raw Dataดาวน์โหลดและวางข้อมูลดิบ

Download raw reports from 3PL, TMS, and ERP, then paste them into the color-coded sheets (green, orange, and red tabs).

ดาวน์โหลดไฟล์ข้อมูลดิบจาก 3PL, TMS และ ERP แล้ววางตามชีทที่กำหนด (แท็บสีเขียว ส้ม และแดง)

2

Refresh Power Query ReconciliationRefresh การกระทบยอดด้วย Power Query

In "TMS Check", enter the DO Creation Date range and click the blue Refresh button to run 3-source reconciliation automatically.

ไปที่ชีท TMS Check ใส่ช่วงวันที่ DO Create Date แล้วกดปุ่มสีฟ้า ระบบจะดึงข้อมูลจาก 3 แหล่งมา Reconcile ให้อัตโนมัติ

3

Refresh Output Tabs (Create DO & PostToRV)Refresh ชีทผลลัพธ์ (Create DO และ PostToRV)

Click "Refresh" to update Create DO (filtered against DO Reconciled) and PostToRV (filtered for Status = Debtor, with the batch key, InvoiceNumber, and Amount).

กด "Refresh" เพื่ออัปเดตชีท Create DO (กรองซ้ำกับ DO Reconciled) และชีท PostToRV (กรองเฉพาะ Status = Debtor พร้อมคีย์แยกก้อน, InvoiceNumber และ Amount)

4

Split into Batch Sheetsแยกข้อมูลเป็นชีทตามรอบโอน

Click the "Split" macro button to partition reconciled records into separate worksheets by carrier and payout date.

กดปุ่ม "Split" เพื่อแยกรายการที่กระทบยอดแล้วออกเป็นชีทย่อยตามขนส่งและวันที่โอนเงิน

5

Review Generated Sheetsตรวจสอบชีทที่สร้างขึ้น

The macro groups invoices into individual sheets and shows a completion dialog. Click "OK".

ระบบแยก Invoice ไปอยู่ในแต่ละชีทอัตโนมัติ และแสดงกล่องข้อความเมื่อเสร็จสิ้น กด "OK"

6

Export Individual Filesส่งออกเป็นไฟล์แยก

Click "Export" to convert each worksheet into an upload-ready Excel workbook.

กดปุ่ม "Export" เพื่อส่งออกแต่ละชีทเป็นไฟล์ Excel แยกตามรอบการโอน พร้อมอัปโหลด

7

Select Target Folderเลือกโฟลเดอร์ปลายทาง

Choose where to save the exported files, either an existing folder or a new one.

ระบุโฟลเดอร์ที่ต้องการเก็บไฟล์ เลือกโฟลเดอร์ที่มีอยู่แล้วหรือสร้างใหม่ก็ได้

8

Clear Workspaceล้างพื้นที่ทำงาน

Click "Clear" to remove temporary split sheets and reset the workbook for the next cycle.

กดปุ่ม "Clear" เพื่อลบชีทย่อยชั่วคราวทั้งหมด และเตรียมไฟล์สำหรับรอบถัดไป

9

Verify Exported Filesตรวจสอบไฟล์ที่ส่งออก

Check the batch files in the target folder. Each is named automatically with the payment date and 3PL code.

ตรวจสอบไฟล์ในโฟลเดอร์ที่เลือก ซึ่งตั้งชื่อตามวันที่รับชำระและรหัสขนส่งโดยอัตโนมัติ

10

Batch Import into TMSอัปโหลดไฟล์เข้า TMS

In TMS, go to Accounting >> Batch List >> Import, attach the file, and select the last-mile carrier and payment date shown in the filename.

ในระบบ TMS ไปที่ Accounting >> Batch List >> Import เลือกไฟล์ แล้วเลือกขนส่ง (Lastmile) และวันที่โอนเงินตามชื่อไฟล์

11

Send Invoice Data to Bulk RV APIส่งข้อมูลบิลเข้า Bulk RV API

In PostToRV, copy the InvoiceNumber and Amount columns and paste them into the Bulk RV API Web App. Use PaidDate/Customer to select the customer and document date.

ในแท็บ PostToRV คัดลอกคอลัมน์ InvoiceNumber และ Amount ไปวางใน Bulk RV API Web App แล้วใช้ PaidDate/Customer เพื่อเลือกลูกค้าและระบุวันที่เอกสาร

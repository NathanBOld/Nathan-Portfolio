01 — Business Caseเหตุผลทางธุรกิจ

Gap Analysis: As-Is → To-Be วิเคราะห์ช่องว่าง: กระบวนการเดิม → กระบวนการใหม่

Each operational pain point is mapped directly to its automated solution. จับคู่ปัญหาหน้างานแต่ละข้อกับโซลูชันอัตโนมัติที่แก้ไขโดยตรง

As-Is · Current StateAs-Is · กระบวนการเดิม
To-Be · Target StateTo-Be · กระบวนการอัตโนมัติ

✕ Off-System Processing การทำเอกสารนอกระบบ

Manual PO creation outside the ERP causes severe operational bottlenecks.

การเปิด PO แบบ Manual นอกระบบ ERP ทำให้เกิดคอขวดในการทำงานหน้างาน

→

✓ Automated Data Capture สกัดข้อมูลอัตโนมัติ

Smart extraction from PO PDF files via LINE OCR turns off-system documents into validated digital data instantly.

อ่านข้อมูลจากไฟล์ PDF ใบสั่งซื้อผ่าน LINE OCR แปลงเป็นข้อมูลดิจิทัลพร้อมตรวจสอบทันที

✕ Delayed Cash Flow Visibility ข้อมูลกระแสเงินสดล่าช้า

Data lag prevents Accounting from accurately updating weekly cash flow reports.

ฝ่ายบัญชีอัปเดตรายงานกระแสเงินสดรายสัปดาห์ได้ไม่แม่นยำ เพราะข้อมูล PO เข้าระบบล่าช้า

→

✓ Real-Time Cash Flow Visibility เห็นกระแสเงินสดแบบ Real-Time

Instant API injection into the ERP upon approval keeps weekly cash flow reports accurate and current.

ส่งข้อมูลเข้า ERP ผ่าน API ทันทีที่อนุมัติ ฝ่ายบัญชีจัดทำรายงานกระแสเงินสดรายสัปดาห์ได้ถูกต้องและรวดเร็ว

✕ Inefficient Approvals การรออนุมัติที่ไร้ประสิทธิภาพ

Physical document routing delays decisions and creates tracking blind spots.

การเดินเอกสารกระดาษทำให้ตัดสินใจล่าช้าและติดตามสถานะได้ยาก

→

✓ Seamless Approval Workflow อนุมัติไร้กระดาษ 100%

Fully paperless, dynamic email approvals enable fast decisions with full status traceability.

ส่งอีเมลขออนุมัติแบบโต้ตอบอัตโนมัติ ผู้บริหารตัดสินใจได้เร็วและตรวจสอบสถานะได้ทุกขั้นตอน

✕ Data Integrity Risks ความเสี่ยงข้อมูลซ้ำซ้อน

High risk of duplicate or incorrect entries when back-filling data into the ERP.

เสี่ยงต่อการคีย์ข้อมูลซ้ำหรือผิดพลาดเมื่อต้องบันทึกลง ERP ย้อนหลัง

→

✓ Systematic Data Governance ควบคุมคุณภาพข้อมูลอย่างเป็นระบบ

Built-in duplicate checks (New / Revision / Locked) and validation rules prevent duplicate payables before ERP integration.

ระบบเช็คเลขที่เอกสารซ้ำ (New / Revision / Locked) ก่อนส่งเข้า ERP ป้องกันการตั้งหนี้ซ้ำซ้อน 100%

03 — Architectureสถาปัตยกรรม

System Architecture & Data Flow สถาปัตยกรรมระบบและการไหลของข้อมูล

Designed around data governance: Google Sheets acts as a staging database for duplicate validation and API-ready formatting before REST API execution into TRCloud ERP.

ออกแบบโดยเน้น Data Governance ใช้ Google Sheets เป็นพื้นที่พักข้อมูล (Staging Area) เพื่อตรวจสอบเอกสารซ้ำและจัดรูปแบบให้ตรงมาตรฐาน API ก่อนส่งเข้า TRCloud ERP

  1. 1 Captureรับข้อมูล PO file via LINE → OCR extractionส่งไฟล์ PO ผ่าน LINE → สกัดด้วย OCR
  2. 2 Validateตรวจสอบ Google Sheets staging: New / Revision / Lockedพักข้อมูลใน Google Sheets: New / Revision / Locked
  3. 3 Approveอนุมัติ Dynamic email approval routingส่งอีเมลขออนุมัติแบบโต้ตอบ
  4. 4 Syncส่งเข้า ERP REST API → TRCloud ERPREST API → TRCloud ERP
